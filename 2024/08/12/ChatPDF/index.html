1.1 与GPT对话询问过程：

问题：
我是一个小白，我需要建立一个chatPDF后端RAG系统：
文档的加载与切割需要利用pdfminer.six库；
embedding过程利用openAI的“text-embedding-ada-002”模型；
向量数据库利用milvus,检索后答案要利用sentence_transformers的CrossEncoder进行Re-ranker；
最终答案利用openAI的GPT3.5-turbo模型生成自然语言返回答案，请问这种代码我应该如何一步一步操作？

此时，ChatGPT依照我的需求会生成了一段后端代码，根据生成的代码进一步完善，补齐需求。

问题：
文本切割我想要做成可以按照指定页码提取文档中的部分文档进行切割，代码应该如何实现？

在本地建立一个名为chatPDF的文件夹作为项目文件夹，用代码编译器打开，我使用的是vscode，你也可以选择其他的，之后将ChatGPT生成的代码复制/逐步手敲（如果是初学者，强烈建议逐步手敲代码加深记忆）到本地的代码文件内，文件名可以设置成apptest.py，这个文件的作用主要用于将首先写完的后端代码进行命令行测试，以及与后续的前后端交互的代码做隔离，因为后续我们还需要加入前端的代码实现交互，这种隔离在后面可以方便快速锁定代码问题出现在哪里。

2.错误二：

a. 报错代码：
paragraph_embeddings = get_embeddings(paragraphs)
embeddings = [embeddings['embedding'] for embeddings in response['data']]
b. 出错原因：
response[‘data’]返回的对象类型是CreateEmbeddingResponse，而不是一个可下标操作的字典。
c. 解决办法：
需要先检查一下CreateEmbeddingResponse对象的结构，然后正确地提取其中的嵌入。
（1）打印response对象，查看向量具体的结构

（2）查看输出：
CreateEmbeddingResponse(data=[Embedding(embedding=[-0.015371694229543209, 0.012382754124701023, -0.015427692793309689, -0.008602828718721867, 0.0011707267258316278, 0.019011622294783592，…，
（3）从CreateEmbeddingResponse对象的结构来看，data属性是一个包含Embedding对象的列表，每个Embedding对象有一个embedding属性。我们需要从每个Embedding对象中提取embedding。
需要将get_embedding函数中的语句替换为：
embeddings = [item.embedding for item in response.data]

a. 报错代码：

SchemaNotReadyException(message=ExceptionsMessage.SchemaInconsistent) pymilvus.exceptions.SchemaNotReadyException: <SchemaNotReadyException: (code=1, message=The collection already exist, but the schema is not the same as the schema passed in.)>

d. 解决办法：
（1）删除并重新创建集合

（2）检查并匹配模式

5.错误五：(继续错误三的延伸问题)

a. 代码出错
candidate_paragraphs = [paragraphs[result.id] for result in results[0]]

IndexError: list index out of range

b. 错误原因
检索过程中存在一个ID超出了paragraphs列表的范围，主要原因是再插入嵌入数据时ID顺序不一致/检索结果ID不总从0开始。

c. 解决办法
在插入数据时将段落和嵌入向量进行正确的关联，并确保在检索结果中正确映射回段落文本。
（1）插入数据时为每个段落生成唯一的 ID
ids = list(range(len(paragraphs)))
collection.insert([ids, embeddings])
（2）检索结果映射（在检索结果中使用这个 ID 映射回段落文本）
注意：在检索结果中，通过 result.id 映射回段落文本，并确保 result.id 不超出 paragraphs 列表的范围。

6.错误六：

a. 代码出错

pymilvus.exceptions.DataNotMatchException: <DataNotMatchException: (code=1, message=The data do not match with schema fields, expect 1 list, got 3)

b. 错误原因
在插入数据到 Milvus 时，遇到 DataNotMatchException 错误。这个错误表明插入的数据与集合模式不匹配在 Milvus 中，插入的数据应该是一个二维列表，其中每个列表项应该与模式中的字段一一对应。

c. 解决办法
（1）确保每个子列表只包含与模式字段对应的值。
（2）你的集合模式包含两个字段 id 和 embedding。在插入数据时，需要将每个段落的 ID 和嵌入向量组合成一个列表，并且数据应该是一个包含多个这种子列表的列表。

在这个调整后的代码中，确保在调用 insert 方法时传递的 data 是一个包含 ID 和嵌入向量的二维列表。这样可以避免 DataNotMatchException 错误。

GPT回复：

4.后续优化

优化方向可以基于两个主要方面：技术精进以及用户体验。
技术方面：
a.增加识别PDF文档内图表的功能；
b.增加多轮对话，保存用户上下文信息，以便下次查询时直接使用；
c.优化处理数据以及与大模型交互的方法，引入一些现有框架例如LlamaIndex、LangChain等，简化代码；
d.引入一些监测的平台,例如langfuse等可以实时监控用户消耗token数等。
用户体验方面：
d.增加用户登录功能，用户可以注册、登录，保存自己的查询记录；
e.优化前端交互界面。
